### 1. The four theorems match the requirements (verified by running and by reading)

Ran: `lake build` exits 0. `lake env lean ReflectContract.lean` exits 0 and prints `[propext, Classical.choice, Quot.sound]` for `reflective`, `reflective_coverage`, `reflective_env`, `tower` and `direct_iff_evalFuel`, and `[propext]` for `direct_deterministic`. No `sorryAx`, no package axiom. A grep of `kernel/Reflect/` finds no `sorry`, `axiom`, `native_decide`, `unsafe`, `partial`, `opaque`, `implemented_by` or `extern`.

Read, `kernel/Reflect/Correctness.lean:7-39`, against `ReflectContract.lean:7-24` and the spec delta:

- No side condition on `p`, `o`, `env` or `k`. All are universally quantified with no hypotheses.
- The comparison is syntactic equality of `Outcome` terms holding `Data`. No decoder appears in any statement. `reifyOutcome` is proved injective (`Proof.lean:489`, axioms `[propext]`), so the data form loses nothing.
- Not vacuous. `builds_and_runs_direct` (`Examples.lean:74`) inhabits the right-hand side by kernel reduction, and `omega_no_interpreter` (`Examples.lean:63`) shows the absence case.
- `level` and `lift` (`Interpreter.lean:132-139`) are what the design says.

Two things narrower than a strict reading of the spec, neither blocking:

- `reflective_env` (`Correctness.lean:23`) is about `evalTerm`, a second closed term, not `interp`. The spec says "`interp` SHALL be one closed term" and then "the same statement at every environment". `interp` is `lam (evalTerm applied to var 0 and [])` so the relation is direct, but the spec text should name `evalTerm` at fold.
- "The same statement at every environment" is proved as the iff only. Coverage at an arbitrary environment exists as the internal `core_sound` (`Proof.lean:496`) and is not a contract theorem. Either export it or have the spec say the env statement is the iff.

### 2. `Direct` and `evalFuel` match the design and each other (read; agreement is also proved)

`Semantics.lean:26-66` and `:69-121` were compared rule by rule with the design's Language section: function before argument; data in function position is `wrong` without evaluating the argument (`appData`, line 32 and line 86); `succ` rules; `cons` is `wrong` on a closure head before the tail (`consHeadClosure`, line 46 and line 108); `dcase` binds head at 1 and tail at 0 (line 62 and line 118); errors propagate. `direct_iff_evalFuel` (`SemanticsProofs.lean:249`) makes agreement a theorem and is restated in the contract.

### 3. `interp` is built from object-language constructors only (verified by running and by reading)

Read: `B.compile` (`Interpreter.lean:18-27`) emits only `var`, `lam`, `app`, `lit`, `succ`, `cons`, `dcase`. The only mentions of `Direct` or `evalFuel` in `Interpreter.lean` are in the comment at lines 6-7.

Ran, in a scratch file outside the repository: a free-variable check gives `true` for both `interp` and `evalTerm` at depth 0 (also closed by `decide`). No program or outcome is smuggled in as a literal.

### 5. Claims not true of the code

a. **`ReflectRun.lean` does not compile (verified by running).** `lake env lean ReflectRun.lean` exits 1. `ReflectRun.lean:28-34` defines `identity`, `delta`, `omega` and `buildsAndRuns` at root while `open Reflect` brings in the same names from `Reflect/Examples.lean:5-12`. Twelve of the 21 `#eval` lines fail with "Ambiguous term", including the headline "program builds code and runs it" (line 55) and the `omega` line (line 56). `proposal.md:34` names this file as the Working surface. `lake build` does not cover it, which is how it slipped. With the four duplicate definitions removed, a scratch copy prints `ok` on all 20 programs and `true, true, true` on the omega line, so the content is sound; the file is broken.

b. **Task 7 (`tasks.md:9`) is checked and is not true as written (read).** It says `Reflect.Examples` holds "the spike's seventeen scenarios as checked statements". `Examples.lean` has nine scenario theorems. The broader set lives in `ReflectRun.lean` as `#eval` lines that print `ok` or `FAIL`; a `FAIL` would not fail the build, so those are runs, not checked statements.

c. **The interpreter was edited after the freeze (read, `git diff 48bc0ad HEAD`).** `design.md:81` says the interpreter is "written and frozen first". `bind` at `Interpreter.lean:53-55` was renamed from `"tg"`/`"rs"` to `"bind.tag"`/`"bind.rest"` in the proof commit. The old names captured the caller's result variable: `bind "rs" "vs"` in the `analysis` arm (line 106) would have passed on the tail of the result instead of the result. This is a real bug the proof found, and the fix is right. It should be recorded in the change, because the same capture pattern is still possible for any future caller: `compile` resolves names by nearest binder with no freshness check.

d. `design.md:10` puts determinism and the fuel theorems in `Reflect.Semantics`. They are in `Reflect/SemanticsProofs.lean`, which the module table omits.

e. `design.md:85-87` still lists `environment-style-simulation` as an unverified hypothesis with "verification: none". The proof landed in environment semantics, so it is verified and the section should go before fold.
