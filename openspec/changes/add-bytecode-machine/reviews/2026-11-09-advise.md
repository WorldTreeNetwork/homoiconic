### 2. "A term with no derivation SHALL never halt" is not what the contract states

`spec.md:17`. The iff in `machine_correct` only excludes halting with an outcome that reads back. It leaves open halting with a `w` where `readOutcome w = none`. The contract file has no statement that closes this.

It is true and nearly free. In a scratch file outside the repo, about ten lines over the worker's `MP.rev` and `MP.halted_unique` proved:

```
strong_rev : run n (load (compile t)) = .halted w → ∃ o, Direct [] t o ∧ w = injO o
never_halts : (∀ o, ¬ Direct [] t o) → run n (load (compile t)) ≠ .halted w
omega_never_halts : run n (load (compile omega)) ≠ .halted w
```

`strong_rev` depends on `propext`, `Quot.sound`. `omega_never_halts` adds `Classical.choice`, inherited from `omega_no_direct` in `Examples.lean:56`. That last one is the universal form of the Divergence scenario, which the run file only samples at 100,000 steps.

### 4. What `machine_correct` guarantees about returned closures

`decomp` drops `checkFun` and `checkData` (`Machine.lean:45,48`), so `readValue` is not injective on closures. Checked by running: `access 0 (access 0 (apply done))` and `compile (app (var 0) (var 0))` decompile to the same term; applied to `data 1`, the compiled one halts `wrong` and the guard-free one reaches `fault`.

- Guaranteed by the stated theorem: the machine halts iff `Direct` has an outcome among those that read back; errors and data results are exact (readback is the identity there); a returned closure decompiles to the right body and environment.
- Not guaranteed by the stated theorem: that a returned closure's code is `comp b done`, so that it behaves like `b` if run further.
- True and proved internally, not exported: the halted value is exactly `injV v` (`MachineProof.lean:487`, and `strong_rev` above). The worker did not lean on the weakness; both directions go through the exact embedding.

For "the machine agrees with direct evaluation" on whole programs, the theorem is not weaker than the requirement. It is weaker than what pausing, moving and disputing will need. Pinning `strong_rev` plus the forward exact form in the contract costs nothing.

## Concluded by reading

### 3. `fault` is claimed unreachable and that is not proved

`design.md:25` and `Machine.lean:84` say `fault` is a state no compiled program reaches. No theorem says so, and the spec delta does not claim it.

- For a term with a derivation it follows: the run halts, `fault` steps to itself, so no earlier state is `fault`.
- For a term with no derivation nothing excludes it. `MP.rev` only takes apart runs that end in `halted`. Proving it needs an invariant over running states that the proof file does not have.

Combined with finding 2: for a divergent term the five theorems allow "runs forever", "faults", and "halts unreadably". Only the first is true; the second is unproved anywhere.
