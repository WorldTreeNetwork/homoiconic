## Independent take (written from Why/What and the living specs, before design, tasks or deltas)

1. Pin the frame byte for byte (magic, kind, status, correlation, budget, offsets) in the living spec. Pin which (kind, status, budget, payload) combinations are accepted. Every other combination is dropped or gets a named error, with no evaluation.
2. Pin one Lean export that takes the program bytes and returns the whole reply. Zig reads only the transport header. The new export must enter zig-host's closed list of exports that evaluate.
3. Pin a binary reply form owned by Wire, with a strict reader, independent of UDP. Say how it relates to `Reflect.reifyOutcome`.
4. Pin the size bounds: no fragments, a stated datagram cap, a fixed reply buffer, and "too large" as its own status. Never truncate. Never rerun a request to retry with more capacity.
5. Pin the device by an allow-list of virtio features, a minimum RX buffer size, and an untrusted used length. Map BARs above 4 GiB before touching them.
6. Pin the fatal path. A native abort or fault in the middle of a request kills the boot visibly, without a fake reply and without announcing readiness again. The client reports a timeout.
7. Refuse: Zig parsing program bytes, an outcome rebuilt from text, readiness before the device and Lean are up, and native tests standing in for KVM.
8. Pin that requests carry no state between them, so a repeated UDP request can safely be evaluated twice. No reply cache, and no claim of exactly-once delivery.
9. Tradeoff: one-datagram UDP caps a program at about 1.2 KB. That is acceptable only with the cap stated and QUIC (q59.30) owning everything larger.
10. Gate: the hardware hypotheses need a real CH54/TAP spike before implementation. A result that contradicts the contract must come back through amendment, not drift into the driver.

## Notes (not owed)

- **Expect a stale base at fold.** `add-interpreted-run` is ACTIVE BUILD and plans to add `reflect_interp` to the same closed list (its `tasks.md`, Fold line). Whichever change folds second will see its `base:` stamp go stale. Under the fold rules that means re-pasting both lists together, not overwriting one with the other. The closed list also still omits `reflect_vm_start` and `reflect_vm_from`. That drift predates this change, but this change now restates it, so the union re-paste is a cheap time to fix it.
- **A Lean `panic!` that does not abort is outside the fatal requirement.** By default, compiled Lean prints the panic and continues with a default value. The reply path reached today (`Wire/Cbor.lean` `get!` after bounds checks, `Reflect` machine, `Wire/Form`) looks guarded, so this is not reachable now. To make "no reply after a panic" hold in the future, the server could call `lean_set_exit_on_panic(true)` during initialization, or the build could audit for unguarded `!` on the served path.
- **What the hook should fail.** The fault-injection hook should make the layer's memory service fail (mmap/brk returning failure) so that Lean's own out-of-memory path runs and reports, for example `INTERNAL PANIC: out of memory` followed by `reflect: exit 1`. If the hook printed and powered off by itself, the test would only test the hook.
- **Process requirements in the living spec.** "Contradictory spike results reopen the contract" and the scenario "Actual guest device" describe the change's process, not the running system. When folding, consider rewriting them as the evidence the spike recorded, rather than carrying a rule about a spike that has already happened.
- The prior note still applies: `[2]` drops the reader's refusal reason. That is fine for version 1.
