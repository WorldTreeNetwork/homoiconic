# Advise read of `design.md` (Opus, fresh context, 2026-11-25)

**Verdict: send-back.** Eleven findings; answered in `design.md`, "The advise read, answered".

1. (Blocker) The charge's own conversion happens before the space check: at the default budget `lstepCostWithin` converts up to 8e8 pieces before `afford` can refuse. Count first, check steps on the count, check space on `lowed` from the count, then convert.
2. (Blocker) The charge table does not follow `lPrim`'s case order: a closure on top halts `wrong` with no walk, and must be charged one, not its environment as a tree. `lanswered` is meaningful only when the step ran the operation, not when it hydrated.
3. (Blocker) The save guard counts a closure's environment as a tree, which doubles with each definition: about 21 definitions or more would be refused. Within it `cut`'s time is nodes times code size (`pieceBytes` of each closure decompiles and compiles). Pointer memo or a stated definition limit.
4. Saving bounds pieces and reopening bounds written size: a VM past about 170000 entries saves a state `vm from` cannot open. One measure for both, and the lifetime limit stated.
5. A pause throws away a count: carry `cells − count` across it.
6. The count misses what the session holds besides the state (a node's processes, the payload's function, `seen`, `Doing.got`).
7. Time that grows with the pieces supplied (each `give` restarts a walk) is bounded per piece, not per turn; hydration across a long stored chain is a new limit. State both.
8. `e.id ∈ part.seen` in `dropWhile` is quadratic in the log.
9. The runtime count on `vm`/`node` contradicts "A turn is a run under its own space with no count": a replay would depend on the runtime. Recommendation: the ledger alone for `vm` and `node`, the runtime count for `keep`.
10. The spec deltas are missing (bytecode-machine three requirements and a new one, state-store, event-log, zig-host).
11. Smaller: the `costWithin` underflow edge, `Data.nodesWithin` for literals, `lowed`/`lanswered` must not recurse, `fullWithin` must count references, the answer exists twice during the step, `trail_held`'s omission needs its real reason, an operation's argument in a kept session is limited by the ledger to about 500000 pieces where `run` has no such limit.
