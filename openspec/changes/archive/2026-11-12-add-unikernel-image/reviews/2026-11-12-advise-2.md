## Independent take recorded before design, tasks, and delta

1. Lean must remain the sole reader, compiler, evaluator, and renderer; image glue may move bytes only.
2. A bootable ELF is insufficient evidence unless the actual Lean package initialization and export execute.
3. The Linux comparison must execute the same generated kernel objects, not compare against remembered expected strings.
4. A clean Linux build must regenerate those objects and record their source and compiler provenance.
5. Success must include bounded VM termination and exact result bytes separated from diagnostic output.
6. Failed allocation, unsupported system calls, and processor faults must stop observably rather than silently corrupt state.
7. Memory must come from usable boot-reported RAM, exclude image and stacks, and handle the mapping ceiling explicitly.
8. A stack guard promise must state whether it covers touching the guard or arbitrary stack-pointer jumps.
9. RDRAND and optional vector-state requirements must be explicit, including behavior when hardware support is absent.
10. Retaining musl lowers custom libc work but accepts archive adaptations and a narrowly supported single-thread runtime path.

## Comparison and resolution

- **R1 — addressed.** `design.md:43` and `:45`, and the delta's Successful reproducible Linux build and Clean provenance sections, now require a successful clean Linux build that runs Lake, compiles generated C, and constructs its own `reflect-linux` oracle. Both binaries must link identical Lean objects and runtime archive copies. Source/toolchain provenance and hashes must invalidate stale or wrong-platform reuse. This removes reliance on partial artifacts from the failing Linux `host/check.sh` link. Acceptance requires source provenance, not merely hashes of whatever objects happened to exist.
- **R2 — addressed.** `design.md:37` pins guard size/alignment, allocator exclusion, IST size and syscall save overhead. The delta explicitly limits the claim to accesses touching the guard and excludes frames that skip it. Guard integrity is now a separate deterministic page-fault check: named address, fault 14, alternate-stack evidence, intact adjacent sentinel, and rejection of successful write, reset or timeout. A runtime stack message cannot discharge it. The deep-source scenario remains an additional workload check, not a universal stack-clash guarantee.
- **R3 — addressed.** `design.md:39` and Bounded syscall CPU state pin the XSAVE floor, XCR0 masks 3/7, the enabled-state size check, alignment, red zone, register exceptions, flags and vector preservation. The preservation scenario requires a clobbering handler and negative controls that remove vector restoration or red-zone protection. Feature rejection is observable before musl entry. These obligations are materially stronger than factorial output alone.
- **R4 — addressed.** `design.md:53` and Complete output and infrastructure errors require allocation and retry using the returned length, without inspecting language text. The large rendering exceeds the initial 65536-byte buffer, compares against the Linux oracle and an independent rendering, and includes the newline and successful exit marker. Embedded-zero input protects the pointer/length boundary. Initialization, allocation and write failures must remain unsuccessful infrastructure outcomes.
- **R5 — addressed.** `design.md:51` and `:55` require the pinned call-path audit, retained runtime initialization, restricted export path, explicit no-op libuv resolution, and re-audit after imports/toolchain changes. Randomness requires the carry flag, at most ten attempts, no fallback, and one checked path for AT_RANDOM, getrandom and /dev/urandom. Absent-feature and exhaustion probes, positive served-request probes, and the frozen-clock factorial check are named. The source audit establishes clock independence and the no-thread path; a single frozen-clock result alone would not establish either generally.
- **R6 — addressed.** The delta's opening requirement now assigns the reader, compiler, evaluator and renderer to Lean and prohibits a language reader or evaluator specifically in non-Lean image code. Lean owns semantics additionally requires source/call-path and link inspection, including identical Lean objects in both executables. This is consistent with the living language partition and Zig host specs.

## Steelman and limits

The strongest remaining concern is that the Linux oracle shares the runtime adaptation and can share its defects. The contract addresses the relevant boundary with source inspection, shared-object provenance, independent factorial/long-rendering expectations and targeted negative probes. It does not claim a new proof of the runtime, libc or boot layer. Requiring a second runtime architecture would expand the work without resolving the intended narrow contract better.

The short original task list still names `onenote.zig`, expected fixtures and three programs, while the revised design requires no ELF-note rewrite and a wider check matrix. Those checklist labels do not replace or reduce the explicit design/delta obligations; implementation must satisfy the current full contract. This is not an additional architectural send-back.
